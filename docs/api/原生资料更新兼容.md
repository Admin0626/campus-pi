# 原生资料更新兼容

负责人于 2026-10-23 明确允许追加 `PUT /me`。前缀 `/api/v1`。既有 API007 `PATCH /me` 保留，两个方法映射同一个控制器方法和 `AccountProfileService.patch`，不复制第二套校验或数据库事务。

此 PUT 是原 PATCH 的兼容别名，仍为**仅更新提交字段**：未提交的资料、隐私设置和头像保留，不按完整替换处理。至少提交一项，仅允许 `personal_bio`（0–500字符）、`address`（0–500字符）、`privacy_settings`（两项布尔值 show_campus/show_personal_bio）及 `avatar_ref`（本人实际上传、用途为 AVATAR 的 file:// 引用）。拒绝角色、余额、认证状态等额外字段；不能使用他人头像引用。

需要有效 Bearer，会话在同一写事务内复核。返回统一 envelope，data 为更新后的本人资料，头像返回临时访问 URL。400 为字段错误，401 为无效会话，403 为文件权限不足；原文件授权和扫描要求不变。重复提交相同资料不会创建第二份头像绑定。

```json
{"personal_bio":"测试介绍","address":"校园自提交接点","privacy_settings":{"show_campus":false,"show_personal_bio":true}}
```

小程序沿用公共 `business-surface` 表单、文件上传和 request 服务层，以 PUT 保存后更新当前会话的资料投影。保存过程中身份发生变化或组件已卸载时，不恢复旧用户数据。官方编译、宿主方法联调与真实微信渲染/真机验收分别记录，不能互相替代。
