# 管理记录查询补充

2026-10-23。基线 112 个接口编号不改。以下查询和参数补充复用现有 Bearer、统一响应、服务端分页和权限，不改变原写事务。

所有分页默认 `page=1&page_size=20`，大小 1–100。`date_from`、`date_to` 为 `YYYY-MM-DD`，按北京时间自然日包含两端；服务端转换成 UTC 的左闭右开区间。反向日期、非法日期和越界分页返回 400。`keyword` 最长 100 字符，参数绑定，不拼接为 SQL 值。

|GET 路径（前缀 /api/v1）|权限|筛选参数|返回 data|
|---|---|---|---|
|`/admin/task-audit-logs`|启用且会话有效的管理员|reward_task_id、keyword（任务名）、to_status、date_from、date_to（审核时间）|items、total、page、page_size；每条含现有日志字段及 task_name、reward_amount、reward_type|
|`/admin/notification-deliveries`|管理员且具 NOTIFICATION_PUBLISH 职责|keyword（通知标题/编号）、delivery_status、channel、date_from、date_to（实际 sent_at）|items、total、page、page_size；每条含既有投递字段及 notification_id、notification_title、publish_status|
|`/admin/users`（原查询补充）|原管理员权限|原条件加 date_from、date_to（注册时间）；原 keyword 增加精确用户 ID 匹配|原分页与脱敏投影；列表增加 last_login_time，尚无会话记录时 null|
|`/admin/dashboard`（原响应补充）|原管理员权限|无|保留原统计，增加 pending_verifications/products/posts/tasks/applications/proofs/reports；都读取实际业务表|

无效会话 401、普通用户 403，通知专项职责不足 403。没有匹配数据返回空数组，不伪造历史记录。全局查询按唯一 ID 倒序，原 `/tasks/{id}/logs` 与 `/admin/notifications/{id}/deliveries` 保持可用。

投递日期按实际发送时间筛选，尚未发送且 sent_at 为空的记录在日期过滤时不会匹配；不加日期可查看待发送/失败状态。免打扰队列的计划时刻继续通过既有通知详情和 outbox 状态查看。

控制台基础指标与待办计数为真实接口；复用的增长/分类图仍明确标为 JSON 模拟数据。这里没有增加真实留存、活跃用户或收入趋势计算。
