# 校园Π接口开发规范

版本 1.0.1 · 通知规则修订 2026年10月21日

共 112 个接口操作、94 个路径；P0 104 项、P1 8 项。本文件描述接口契约，不表示全部实现；当前实现与运行证据见管理后台实施清单。已有数据库验证不能替代接口运行验收。

## 阅读方法

先阅读统一约定和新增依赖，再按模块查接口。每个接口的请求体和响应data引用文末对象字典；完整成功响应均使用统一包装。OpenAPI文件与本文件由同一份接口模型生成。

### 文档定位

版本1.0.1，初版2026年10月17日，通知规则按负责人2026年10月21日答复修订。本规范面向用户端、管理端及服务端开发，描述待实现的HTTP契约。P0为首期开发目标，P1为依赖外部服务或补充数据模型后实施。逐项“未实现”及OpenAPI状态保留初版设计元数据；当前进度以docs/development中的真实验证记录为准，不能据契约样例推定运行成功。

### 依据与优先级

业务基线为校园Π软件工程设计报告修订版的3.3数据字典、3.4加工说明、3.5数据库设计、4.3统一规则、5.1原型及第6章；物理字段以01_数据库结构.sql为准，12个事务入口参考02_核心业务事务.sql。接口地址、字段对象、分页、错误码、会话时限等为本规范新增约定。若正文概述或旧原型与4.3冲突，按4.3及本规范的范围执行。

### 地址与格式

根路径/api/v1；OpenAPI servers使用相对地址，不虚构已部署服务器。默认application/json; charset=utf-8。字段采用snake_case；请求只允许已定义字段，未知字段400。不存在或越权资源统一404。P1路由注册后未启用统一501。

### 身份与权限

Authorization: Bearer <access_token>。令牌为至少32字节随机不透明值，服务端只保存其摘要；绝对有效期2小时、闲置30分钟，二者先到失效，无自动刷新。本版服务端维护可撤销会话，管理员禁用或改角色后立即失效。所有操作者均取当前会话，绝不信任请求体的user_id、role、reviewer_id。

### 管理职责

users.role仅USER和ADMIN。认证审核、订单处理、举报处理、通知发布、审计及角色管理是新增服务端权限配置；默认全拒绝，再由受控配置授权到明确管理员。普通ADMIN不能任意查看私密文件或调整角色。初始化管理员由离线受控运维完成，不提供公开管理员注册。

### 数据类型

所有BIGINT编号及计数均为字符串；分类INT、分页和小范围数量为整数。金额全部十进制字符串，不使用JSON浮点。示例统一为合成数据，example.invalid不是运行地址。字段的可空性、长度和枚举见数据对象字典；必填代表响应必须出现，nullable字段可为null。

### 时间和排序

输出时间为UTC RFC3339毫秒，例如2026-10-17T02:00:00.000Z；数据库DATETIME无时区，服务连接和应用必须统一UTC。用户界面转换为Asia/Shanghai。列表默认page=1、page_size=20，最大100；每个接口明确稳定的次级主键排序。超出末页返回空items，total为字符串。

### 响应约定

成功HTTP状态以接口为准，统一code=OK、message=成功、data为对象、request_id为追踪编号。不返回204，删除成功data={}。失败使用真实HTTP错误状态，code为稳定业务错误码，data=null，errors为空数组或字段错误项；禁止统一HTTP200包装失败。

### 幂等与重试

标明幂等键的接口必须传Idempotency-Key，8至64个字母数字下划线连字符。作用域=操作者+HTTP方法+规范化路径+键，保存请求摘要与业务结果24小时。同键同体返回原状态码与data，request_id按当前请求生成；同键异体409，同键处理中409并Retry-After:2。创建、审核、结算、发送必须可重试；幂等记录未持久化不得宣称达标。

### 事务调用

现有12个存储过程内部已经START TRANSACTION/COMMIT，不能外包在调用方未提交事务中；管理员驳回接取申请等没有过程的分支须补服务事务。开发时必须选定并统一采用现有过程或等价服务层事务。幂等状态与SQL内事务无法天然原子：必须保存目标资源标识、按业务唯一键恢复完成结果，并测试提交后响应丢失；不得在处理中超时后盲目重放。

### 文件与隐私

新增文件元数据存储必须绑定owner_id、purpose、引用对象、扫描状态和保留期。仅接收实际探测的PNG/JPEG/WebP；认证、任务、售后另支持PDF。头像最大2MiB，其余图片最大5MiB，PDF最大10MiB；拒绝SVG/HTML与可执行内容。上传单文件，业务附件最多9个。未绑定文件24小时回收，绑定凭证禁止被普通用户直接删除；访问地址60秒有效，私密响应Cache-Control:no-store。

### 联系信息和密码

密码仅TLS传输、禁止日志、Argon2id完整编码保存。手机号和邮箱存在唯一字段不等于所有权已验证。密码找回必须增加联系信息验证状态及挑战存储，未完成前关闭；发码60秒间隔、同目标每小时5次、挑战有效5分钟且最多5次错误。登录按账号及来源限流，默认5分钟5次失败后锁该组合15分钟并429；验证码和密码均不返回。

### 同校区交易

未认证用户可浏览公开内容并提交认证；商品发布购买、任务发布接取需实名和校园认证通过。校区来自可信校区清单，交易校区与当前通过认证一致；修改校区先作废旧校园交易资格，再审核新申请。帖子当前无campus字段，不伪造帖子校区过滤。

### 匿名与私密字段

匿名帖子author=null且author_label=校园同学，禁止返回publisher_id、真实作者头像URL或含作者ID的资源链接。本人和管理列表也沿用匿名展示对象；后台在内部保存真实发布者用于审计。公开用户摘要不含联系方式、实名、学号、地址及证据；认证和举报队列只返回摘要，详情再按职责授权。

### 库存与价格

商品下单从数据库读取价格快照并锁定库存，客户端不传总价或库存变更。预占库存后仅待支付取消释放一次；已有履约中订单时不允许替换商品关键资料和库存。P0校园自提运费固定0；快递运费、物流模型未定前不开放快递下单。

### 任务奖励

积分先期采用受控测试或运营授予，禁止前端加分。未开户余额视图为0，不凭注册赠送真实资金；奖励大于0，积分必须整数。现金账本只做合成验证，P0生产关闭现金发布。任务只通过发布、审核、凭证及取消入口迁移，不开放任意status更新或进行中重新分配。

### 通知发布

P0只开放站内通知。通知发布先审核内容和目标，固定接收者快照后建立接收和投递记录；通过持久异步任务投递。publish_status=已发送仅表示发布快照及预建接收记录完整，实际进入本人收件箱须站内attempt成功；免打扰中的预建记录不可见。关闭则不接收，安全通知也遵守偏好；排队时修改时段会重新计算。短信邮件投递结果以各attempt记录为准。短信邮件只用于安全消息，不能用开关绕过渠道限制。活动本版用帖子或公告承载，报名和活动专表不在范围。

### 支付与售后

P1支付只预留支付申请契约，未选支付供应商前不可实际联调。供应商回调验签、重放保护、订单金额币种比对、支付请求和退款请求表须另补；不得用前端成功跳转修改已支付。售后须保存申请前订单状态和退款余额预占；现有25表不足以安全表达完整退款恢复过程。

### 接口启用条件

新增依赖包括会话、文件元数据、幂等记录、管理员职责权限、联系信息验证/验证码、通知目标快照/发件箱/持久任务、支付退款及售后原状态。可以采用新增表或具备等价持久性的服务；本次不更改原25表SQL。P0接口也要在所需依赖实现并验收后才可宣称可用。

### 新增存储与幂等一致性

现有过程原样不能保证HTTP幂等记录与业务提交原子一致。首选以等价服务层事务把幂等占位、资源写入、结果关联和发件箱一次提交；也可扩展存储过程接收请求键并同事务保存结果。不能给现有自提交过程套外层事务。待实现依赖另包括可靠订单编号生成，以及同校区已通过学号的唯一登记与并发保护。

## 错误码

|错误码|HTTP|含义|
|---|---|---|
|VALIDATION_ERROR|400|字段缺失、格式错误、未知字段、空PATCH|
|UNAUTHENTICATED|401|令牌缺失、失效或已注销|
|ACCOUNT_DISABLED|403|账号已禁用|
|FORBIDDEN|403|角色不符或禁止的业务动作|
|VERIFICATION_REQUIRED|403|实名或校园认证未通过|

|UNIQUE_CONFLICT|409|用户名联系方式或业务唯一键冲突|
|STATE_CONFLICT|409|状态不允许当前操作或被其他请求改变|
|INSUFFICIENT_STOCK|409|库存不足|
|INSUFFICIENT_REWARD|409|可用奖励余额不足|
|IDEMPOTENCY_CONFLICT|409|同一幂等键用于不同请求|

## 业务联调顺序

### 注册认证与商品发布

实名通过后再提交校园认证；每种凭证先上传再引用。商品发布返回待审核/已下架，管理员通过后才公开在售。

1. API001 `POST /auth/register`
2. API002 `POST /auth/login`
3. API013 `POST /files`
4. API011 `POST /me/verifications`
5. API078 `POST /admin/verifications/{verification_id}/review`
6. API018 `POST /products`
7. API080 `POST /admin/products/{product_id}/review`

### 任务从发布到一次结算

发布冻结奖励；提交申请时任务仍待接取；管理员批准一名申请者后创建任务订单并进入进行中；提交凭证进入待验收，验收通过原子结算。补充凭证回进行中，未通过进入未完成后由管理员关闭。

1. API036 `POST /tasks`
2. API089 `POST /admin/tasks/{reward_task_id}/publication-review`
3. API038 `POST /tasks/{reward_task_id}/applications`
4. API091 `POST /admin/task-applications/{application_id}/review`
5. API041 `POST /tasks/{reward_task_id}/proofs`
6. API093 `POST /admin/task-proofs/{proof_id}/review`

### 商品下单与取消库存

首期仅验证创建待支付订单及取消释放库存。真实支付未接入时不得伪造已支付；后续支付发货收货在P1验收，支付结果只能来自可信渠道。

1. API046 `POST /orders/product`
2. API048 `GET /orders/{order_id}`
3. API049 `POST /orders/{order_id}/cancel`

### 消息发送阅读和举报

复用规范顺序会话；发送者与接收者从会话推导；用after_msg_id增量拉取并去重；只有接收者标记已读。举报管理员仅访问案件关联消息。

1. API057 `POST /chat-sessions`
2. API060 `POST /chat-sessions/{session_id}/messages`
3. API059 `GET /chat-sessions/{session_id}/messages`
4. API061 `PUT /messages/{msg_id}/read`
5. API063 `POST /messages/{msg_id}/reports`
6. API102 `POST /admin/message-reports/{report_id}/review`

### 通知从草稿到阅读

先建立接收者快照与站内接收记录，再异步投递；读取详情不自动改已读，前端显式调用read和click。渠道成功不等于用户阅读。

1. API104 `POST /admin/notifications`
2. API107 `POST /admin/notifications/{notification_id}/publish`
3. API109 `GET /admin/notifications/{notification_id}/deliveries`
4. API065 `GET /me/notifications`
5. API067 `PUT /me/notifications/{notification_id}/read`
6. API068 `PUT /me/notifications/{notification_id}/click`
