# 商品订单改为线下交易

2026-10-24，按项目负责人要求取消线上支付，商品仅通过校园自提进行线下交易。悬赏任务的内部积分冻结、结算保持原流程。平台不代收款、不生成支付凭证，也不执行商品退款。AppID与微信账号绑定不具备支付能力。

## 用户使用流程

1. 买方打开商品，选择“预约线下交易”，填写数量和自提交接地点，提交后预占库存，状态为“待线下交易”。
2. 通过已有私信约定见面时间、地点，当面检查商品并自行结算。页面展示的订单金额来自下单时的商品价格快照。
3. 卖方在“我的订单 → 卖出”打开订单，点击“确认已线下交付”，状态进入“待确认收货”。
4. 买方确认已验货、收货并完成双方线下结算后，点击“确认已线下收货”，订单“已完成”。系统只记录双方声明的进度，无法核验线下款项。
5. 卖方尚未确认交付时，买方可以取消；有订单处理职责的管理员也可以取消，库存只释放一次。交付后不可再取消或恢复已售库存。退换或款项问题由双方线下协商。

## 接口

统一前缀`/api/v1`。下表变更操作须登录并携带`Idempotency-Key`；重复同键返回原结果，新键重复操作返回409。所有请求只接受契约内字段。

|编号|方法与路径|请求与权限|结果|
|---|---|---|---|
|API046|`POST /orders/product`|同校区已认证买方；`product_id`字符串、`quantity`整数、`shipping_address`非空字符串1–500字|201；服务器固定`trade_channel=OFFLINE`，状态“待线下交易”，按价格快照预占库存|
|API049|`POST /orders/{order_id}/cancel`|买方；空请求体；尚未交付|200；已取消，恢复一次库存|
|API050|`POST /orders/{order_id}/shipping`|卖方；空请求体；待线下交易|200；待确认收货，填写`shipping_time`。路径为既有契约兼容名称，含义是线下交付，不涉及快递|
|API051|`POST /orders/{order_id}/receipt`|买方；空请求体；待确认收货|200；已完成，填写`completion_time`|
|API097|`POST /admin/orders/{order_id}/cancel`|管理员；`{"reason":"取消原因"}`；尚未交付|200；取消并记录审计，不返回交接地址|

查询继续复用`GET /me/orders`、`GET /orders/{order_id}`及管理端订单接口，返回新增`trade_channel`。列表交接地址仍为null，双方详情及具备订单处理职责的管理详情才能读取。

正常状态：**待线下交易 → 待确认收货 → 已完成**；交付前可以进入**已取消**。

- 无登录401；订单外用户404；买卖角色不符403；乱序、重复新键、交付后取消409；不允许提交付款标记、金额或自选渠道，未知请求字段400。
- 每次状态变更均在数据库事务内锁订单，沿用会话校验、幂等记录和审计。取消另锁商品，保证与交付竞态不会同时成功。
- `actual_amount`为平台账本记录，线下商品始终`0.00`；`payment_method`、`payment_time`、`payment_transaction_no`始终null。页面不把它展示为“买方实际支付0元”。`total_amount`表示下单约定金额。
- `trade_channel=null`的既有商品记录保留为历史订单，不能走新的线下确认流程。任务订单仍由任务验收流程驱动。

## 删除的能力

API052已退役，编号不复用。原线上支付申请路径不注册，调用返回404；支付请求、支付凭证及其OpenAPI模型已删除。有效契约为111个操作（P0 106，P1 5），不提供线上支付或商品退款接口。

任务零金额争议继续复用API053/056/099；商品分支会拒绝处理并提示双方线下协商，无法产生退款流水。原始Word设计稿及旧SQL中的历史付款字段保留档案价值，不再代表当前功能计划。当前开发以本说明、[OpenAPI](campus-pi-openapi.json)和更新后的Markdown规范为准。

## 数据库升级

已有库先备份并停止本项目后端，确认目标库后执行[V009](../../database/migrations/V009__offline_product_trade.sql)一次，再启动新版。脚本不删除表或订单、不重置库存、不覆写已付款历史。

V009增加`trade_channel`和线下状态约束；仅无金额、无支付记录、无履约时间、无售后工单的原待支付订单转换为线下待交易。其他历史订单只保留原始事实。原商品下单、取消存储过程也被替换，避免直接调用旧过程生成新的待支付订单。

新电脑使用[本地初始化SQL](../../database/init.sql)时已包含V009，不能重复执行；已有库不能重新导入初始化SQL。回退旧程序前须单独评估新增线下状态，不能通过重新播种数据库回退。

## 验收

买卖双方分别登录完成上述流程；检查金额快照、库存、角色按钮、时间、审计与相同幂等键重放。验证买方不能提前收货、卖方不能替买方收货、无关用户不可读写订单、取消与交付并发只能一方成功，平台账本与奖励余额不因商品交易变更。
