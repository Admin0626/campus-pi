# 管理批量操作接口补充

2026-10-22，作为接口规范1.0.1的增量扩展。原112个API编号及九人归属不变。本扩展对应负责人确认的“逐条独立处理，保留已成功结果，并列出失败项”，不提供整批回滚语义。

所有路径以 `/api/v1` 为前缀。必须使用有效管理员 Bearer 会话，客户端不能指定操作者、职责或会话版本。创建与查询均重验管理员身份；只能查询本人创建的批次，他人的批次返回404。

|方法及路径|用途|业务归属／复用的单条服务|
|---|---|---|
|POST `/admin/batch-operations/users`|批量启停用用户|A，API074|
|POST `/admin/batch-operations/products`|批量审核商品|C，API080|
|POST `/admin/batch-operations/posts`|批量审核帖子|D，API086|
|POST `/admin/batch-operations/tasks`|批量审核任务发布|E，API089|
|GET `/admin/batch-operations/{batch_id}`|查询本人单批结果|公共批量基础设施，业务模块共用|
|GET `/admin/batch-operations?kind=users`|查询本人指定类型最近10个批次|kind枚举：users/products/posts/tasks|

## 提交

请求头 `Idempotency-Key` 必填，8–64位字母、数字、下划线或连字符。以下两类请求体只允许列出的字段，未知字段400。

```json
{"ids":["123","124"],"account_status":"DISABLED","reason":"管理员核对后停用"}
```

```json
{"ids":["123","124"],"decision":"通过","reason":"材料符合发布要求"}
```

|字段|约束|
|---|---|
|ids|string数组，1–50条，不得重复；每次UI选择仅限当前页|
|数字业务编号|必须是正整数字符串，不能传JSON数字或超出有符号BIGINT范围|
|帖子编号|string，非空、最多50个Unicode字符，无控制字符，保留原编号|
|account_status|仅users使用；ACTIVE或DISABLED|
|decision|其余三类使用；通过或驳回|
|reason|string，去首尾空白后1–500个Unicode字符|

接收后返回202和通用成功信封，表示批次及项目已落库，不表示全部成功。整个请求体不合法时返回400且不创建批次；不存在、状态冲突、自我停用、材料或积分校验失败等是逐项失败，其他项继续处理。

```json
{
  "code":"OK","message":"成功","request_id":"请求追踪编号",
  "data":{
    "batch_id":"xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
    "kind":"products","action":{"decision":"通过","reason":"材料符合发布要求"},
    "status":"COMPLETED","total":2,"succeeded":1,"failed":1,"pending":0,
    "created_at":"2026-10-22T00:00:00Z",
    "items":[
      {"target_id":"123","item_status":"SUCCEEDED","http_status":200,"error_code":null,"result_message":"操作成功"},
      {"target_id":"124","item_status":"FAILED","http_status":409,"error_code":"STATE_CONFLICT","result_message":"该记录已经审核"}
    ]
  }
}
```

示例文案用于说明结构，实际失败文案沿用单条服务。批次status为PENDING或COMPLETED；项目item_status为PENDING、SUCCEEDED或FAILED。待执行项的http_status/error_code/result_message为null。数量是最多50的普通整数，业务编号仍为字符串。结果不返回账号联系方式、作者身份、文件临时URL、会话摘要或数据库异常文本。

GET单批返回200及同样data结构。最近批次返回 `data.items` 数组，每个元素为上述完整批次结构，按创建时间倒序，上限10；该列表不是全量历史分页接口。任何已知batch_id仍可通过单批接口查询。

## 执行、幂等与失败恢复

- 同一操作者、同一key、相同规范化请求返回原batch_id和最新结果；字段顺序不影响重放。改变类型、ID顺序、选项或原因返回409 IDEMPOTENCY_CONFLICT。批次记录保留期间该key不会按单条接口的24小时缓存策略过期。
- 每项拥有独立数据库事务，原业务修改、原审计、原单条幂等记录及该项成功结果一起提交。单条失败先完整回滚，再独立保存失败结果。不得将外层整批事务套在循环上。
- 后台worker逐项处理，跨实例先锁现有管理写锁，再检查并锁项目；已完成项目不会重复执行。进程退出使未提交项回滚为待执行，重启后恢复；已提交的成功和失败均保留。
- 执行时重新检查提交时的会话、账号启用状态、auth_version及管理员角色，不替后台任务续期。会话撤销或过期、改密、账号停用、降级后，剩余项目可能失败；重新登录不会自动重跑原失败项。
- HTTP响应丢失时必须重发原请求和原key查询原批次。已失败项目不因依赖恢复而自动变为成功；“只重试失败项”创建新key和新批次，仅包含原失败ID。
- 用户自我停用和最后一名启用管理员保护继续生效；不扩展批量改角色、删除用户、奖励结算或订单退款。任务拒绝沿用逐任务冻结/释放校验，默认现金关闭时单条501，不能绕过。
- 不因执行批量审核自动发通知；R14审核结果自动通知仍为后续工作。

## 错误与接入

请求级错误沿用通用信封：400参数/幂等键错误，401会话无效，403非管理员，404本人批次不存在，409幂等冲突，503数据库暂不可用。条目失败包含原业务HTTP状态及安全错误码，例如NOT_FOUND、STATE_CONFLICT、UNAUTHENTICATED、FORBIDDEN、FEATURE_NOT_ENABLED、DEPENDENCY_UNAVAILABLE。不能只检查请求级202就提示“全部成功”。

执行依赖V007及配置 `campus.admin-batches.worker-enabled=true`（环境变量 `ADMIN_BATCH_WORKER_ENABLED=true`），默认false。轮询间隔默认1000ms，每轮最多20项。本机验收进程已显式开启；共享库和生产库尚未升级或部署。前端每秒查询当前待执行批次，查询失败停止自动轮询并提供手动继续，避免无限失败请求。

前端复用 `AdminBatchActions.vue` 和 `useAdminSelection.js`，将模块种类、当前页所选ID、加载状态传入，完成后刷新原列表。不要新增四套独立确认/结果组件；不要改原页面的公共布局尺寸。
