# 校园Π本地部署说明

适用版本：2026年10月24日后的 main 集成版本。面向第一次在自己电脑上运行项目的成员，以下以 Windows PowerShell、仓库 `D:\demo_series\campus-pi` 和本机 MySQL 为例。仓库放在其他位置时，替换路径即可。

首次建议先跑通 Web 用户端和管理后台，再导入微信小程序。本文使用独立的 `campus_pi_local` 数据库，初始化一个管理员和基础分类，普通业务数据由页面逐步创建。已有日常开发库或人工验收库不需要重新初始化。

## 一 项目有哪些部分

|目录|属于哪一部分|作用|怎么运行|
|---|---|---|---|
|`backend/`|后端|Java17与Spring Boot，提供账号、商品、任务、订单、审核、通知等接口；连接MySQL，处理文件|Maven启动，或运行打包后的JAR|
|`frontend/`|Web前端|Vue用户端和管理后台在同一个工程；两者共用后端|开发时npm run dev；打包后页面由后端提供|
|`miniprogram/`|微信小程序前端|原生WXML、WXSS、JavaScript，包含首页、发现、发布、私信、个人及公共业务组件|导入微信开发者工具，不是运行Vue，也不是另一个后端|
|`database/`|数据库材料|结构、事务、迁移、初始化及可选人工验收数据|通过MySQL客户端执行SQL|
|`config/local/`|共享配置模板|提供本地后端配置项；真实配置另存`.local`|复制模板后修改私有副本|
|`scripts/`与`docs/`|辅助脚本与文档|构建检查、数据库工具、接口、操作与答辩说明|按相应说明使用，不是单独的业务服务|

客户端调用关系：浏览器或微信小程序 → Spring Boot接口 → MySQL与受控文件。前端不直接连接数据库。管理员页面和普通用户页面使用同一个后端，靠登录身份、职责与对象权限区分操作范围。

|常用端口|用途|是否必须启动|
|---|---|---|
|3306|你安装的MySQL服务，实际端口可自行调整|必须|
|8080|后端；打包模式也在这里提供Web页面|必须|
|5173|Vue开发服务器，代理接口到8080|仅分开开发前端时需要|
|33320、33321、8082|本项目已有独立开发库与人工验收环境的示例端口|按本文首次安装时不需要另开这些服务|

## 二 准备环境并取得代码

安装 Git、JDK17、Maven3.6.3及以上、Node.js22.12及以上和MySQL8.0.16及以上。本文的SQL使用MySQL8语法，不能直接导入SQLite、SQL Server或MariaDB替代库。普通部署直接使用已生成SQL，不需要先安装Python。

新电脑可执行：

```powershell
git clone https://github.com/Admin0626/campus-pi.git D:\demo_series\campus-pi
Set-Location D:\demo_series\campus-pi
git switch main
```

如果代码已经存在，先确认自己的未提交内容已妥善保存，再按团队流程更新，不要重复clone到同一个目录。

```powershell
java -version
mvn -version
node -v
npm -v
mysql --version
```

Java和Maven都必须实际使用JDK17。若电脑默认是Java8，可仅在当前PowerShell设置：

```powershell
$env:JAVA_HOME='D:\Java\jdk-17.0.12'  # 换成你的JDK17目录
$env:Path="$env:JAVA_HOME\bin;$env:Path"
java -version
mvn -version
```

`mysql`找不到时，将已安装的MySQL `bin`目录加入当前终端PATH，示例：

```powershell
$env:Path="C:\Program Files\MySQL\MySQL Server 8.0\bin;$env:Path"
```

确认MySQL服务已经运行，能用自己的数据库管理员账户连接。项目不会替你设置或重置MySQL root密码。

## 三 初始化数据库

使用[database/local/init.sql](../../database/local/init.sql)。这是一份完整的、可直接执行的本地初始化SQL，已合并原25表结构、12个设计过程、4个触发器以及V001至V008迁移，最终为40张应用表。它与旧的25表基线不是两套不同业务模型。

初始化结果：

- 数据库：`campus_pi_local`。
- 管理员：`admin`，本地测试密码：`123456`，用户ID为1。
- 五条基础分类记录，管理员的积分和现金余额均为0。
- 不生成普通用户、商品、订单、任务、认证材料或测试资金，不接通任何真实支付。

这是首次安装脚本，不是升级或重置脚本。第一条建库语句故意不用IF NOT EXISTS；同名库已存在时应报错停止，不能删掉原库来重试，也不要添加`--force`继续执行。DDL不具备整批事务回滚，首次中途失败应保留报错并检查已创建结构。

在仓库根目录的PowerShell执行以下命令。这里借用cmd完成文件输入重定向，整个SQL作为MySQL批处理输入；遇到SQL错误即停止，不受PowerShell旧版本管道编码影响。提示输入的是你自己的MySQL root密码，不是项目管理员密码。

```powershell
Set-Location D:\demo_series\campus-pi
cmd /d /c "mysql --default-character-set=utf8mb4 -h127.0.0.1 -P3306 -uroot -p < database\local\init.sql"
```

也可使用Navicat或其他支持MySQL DELIMITER的工具执行整个SQL文件，必须开启遇错停止。不要逐个分号拆分过程，也不要在已存在业务数据的库上忽略建库失败继续执行。macOS或Linux的终端可直接使用同样的`mysql ... < database/local/init.sql`形式。

成功时末尾显示数据库名、`table_count=40`及管理员`ID=1`。数据库里暂无商品和任务是正常结果。

接着为应用建立专用数据库账号。再次登录MySQL管理员客户端：

```powershell
mysql -h127.0.0.1 -P3306 -uroot -p
```

在`mysql>`提示符中执行下列SQL，密码先替换成你自己设置的数据库应用密码。这个账户只允许本机连接，不给建表或管理其他库的权限：

```sql
CREATE USER 'campus_pi_app'@'127.0.0.1' IDENTIFIED BY '请先替换为你设置的数据库应用密码';
GRANT SELECT, INSERT, UPDATE, DELETE ON campus_pi_local.* TO 'campus_pi_app'@'127.0.0.1';
EXIT;
```

若该MySQL账号已存在，核对它的用途和密码；不要通过删除或重设他人账号处理。SQL初始化不会自动更改数据库账号。后续仍需升级结构时，使用[增量迁移登记](../../database/migrations/README.md)中的适用迁移，不能重跑首次安装脚本。

## 四 配置后端

复制[本地配置模板](../../config/local/application-local.example.yml)到被Git忽略的本机目录：

```powershell
New-Item -ItemType Directory -Force .local/local-deploy | Out-Null
Copy-Item config/local/application-local.example.yml .local/local-deploy/application-local.yml
```

此复制步骤仅在首次准备时执行。已有私有配置时直接编辑，避免再次复制模板覆盖自己的密码和密钥。

打开`.local/local-deploy/application-local.yml`，按下表填写。该文件不提交GitHub，也不复制到`backend/src/main/resources`。

|配置项|怎么填写|
|---|---|
|spring.datasource.url|本机MySQL地址、端口、库名；默认127.0.0.1:3306/campus_pi_local|
|spring.datasource.username|上一步创建的campus_pi_app|
|spring.datasource.password|上一步设置的数据库应用密码，不是123456|
|campus.auth.idempotency-secret|自行生成并保存至少32字符的随机值，重启保持不变|
|campus.auth.local-short-password-admin-id|保留1，仅使本次创建的本地管理员可使用短测试密码|
|campus.admin.duties-json|模板已给ID1分配本地管理职责；换管理员ID必须对应修改|
|campus.verification.allowed-campuses-json|初始为本地测试校区，用户申请校园认证时需使用这个名称|
|campus.files.root|改成自己电脑上的绝对文件目录，保留在静态网页目录之外|
|campus.files.public-base-url|保留http://127.0.0.1:8080；后端改端口时一并修改|
|campus.files.scanner-executable|需要上传图片或认证材料时，填写实际Defender扫描器路径，见下一段|

可以用PowerShell生成随机值，将输出复制到私有配置的`idempotency-secret`，随后妥善保存：

```powershell
$keyBytes = New-Object byte[] 32
$keyGenerator = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$keyGenerator.GetBytes($keyBytes)
$keyGenerator.Dispose()
([System.BitConverter]::ToString($keyBytes)).Replace('-','').ToLowerInvariant()
```

文件上传当前实现的是Windows Defender扫描适配。在Windows中查看已安装的扫描器位置：

```powershell
Get-ChildItem 'C:\ProgramData\Microsoft\Windows Defender\Platform\*\MpCmdRun.exe' |
    Select-Object -ExpandProperty FullName
```

从结果中选择实际存在的路径，用正斜杠写入私有配置，例如`C:/ProgramData/Microsoft/Windows Defender/Platform/实际版本/MpCmdRun.exe`。保留`scanner-provider: DEFENDER`。扫描器没配置时，账号登录和列表仍可运行，但上传会明确提示扫描服务未配置；当前没有完成Linux或macOS扫描器适配，不能将“关闭扫描也上传成功”当作解决方法。

模板启用了通知和批量操作worker，分别驱动持久投递与批次执行；现金仍关闭，微信真实换码仍关闭。根目录`.env.example`是配置项说明，Spring Boot不会自动加载根目录`.env`，不能只改那份文件就认为配置完成。

## 五 启动Web服务

### 方式A 打包后只运行一个后端服务

适合首次本机使用和答辩演示。所有命令都在仓库根目录执行：

```powershell
npm --prefix frontend ci
npm --prefix frontend run build
mvn -B -f backend/pom.xml clean verify
```

先构建Vue，再构建Java；后端打包会将`frontend/dist`放入JAR。此时不需要单独启动5173。

```powershell
$localConfig = (Resolve-Path .local/local-deploy/application-local.yml).Path.Replace('\','/')
java -jar backend/target/campus-pi-server-0.0.1-SNAPSHOT.jar "--spring.config.additional-location=file:$localConfig"
```

保持终端开启，看到服务在8080启动后访问：

|地址|页面|账号|
|---|---|---|
|http://127.0.0.1:8080/login|Web用户登录|先注册普通账号，再登录|
|http://127.0.0.1:8080/register|注册|普通账号新密码要求12至64位|
|http://127.0.0.1:8080/admin/login|管理后台登录|本地admin / 123456|
|http://127.0.0.1:8080/admin|管理工作台|登录管理员后进入|

不要通过`frontend/dist/index.html`文件直接打开页面，也不要把`frontend`当成Java后端启动。Web的用户页面与管理后台不需要分开打两个包。

### 方式B 前后端分开开发

改Vue页面时使用两个PowerShell终端，各自进入仓库根目录。终端一启动后端，外部配置路径必须是绝对路径；Maven插件启动的工作目录可能是backend，不能只传仓库根目录的相对配置位置。

```powershell
$localConfig = (Resolve-Path .local/local-deploy/application-local.yml).Path.Replace('\','/')
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.arguments=--spring.config.additional-location=file:$localConfig"
```

终端二启动Vue：

```powershell
npm --prefix frontend ci
npm --prefix frontend run dev
```

此模式访问`http://127.0.0.1:5173/login`与`http://127.0.0.1:5173/admin/login`。Vite把`/api`和`/file-content`代理到8080。`localhost`与`127.0.0.1`不要在同一轮测试中随意混用。后端改端口时，将`frontend/.env.example`复制为`frontend/.env.local`，修改`CAMPUS_API_TARGET`并重启Vue。

两种方式选择一种即可。方式B更新Vue无需每次重打JAR；方式A修改Vue后必须重新构建并打包。后端与Vue终端按Ctrl+C停止；MySQL独立运行。Windows重打包前先停止使用旧JAR的本项目进程，避免文件占用错误，不要结束电脑上其他Java项目。

## 六 微信小程序在哪里 怎样运行

小程序目录是仓库下的`miniprogram/`。它也访问上述Spring Boot，不连接MySQL，不使用Vue的5173端口作为API服务。小程序开发者工具与Web浏览器可以共用本机8080后端。

1. 安装微信开发者工具并登录具有相应项目权限的微信账号。
2. 在仓库根目录首次复制配置模板；本机已经配置过就直接检查原文件，不覆盖。

```powershell
Copy-Item miniprogram/project.config.example.json miniprogram/project.config.json
Copy-Item miniprogram/config.example.js miniprogram/config.js
```

3. 在本机`project.config.json`填自己的小程序AppID。共享模板保持空值，本文不记录真实AppID。AppSecret只允许由后端私有配置读取，不放进小程序。
4. 编辑本机`miniprogram/config.js`。开发者工具联调时可设为：

```javascript
module.exports = {
  apiBaseUrl: "",
  devtoolsApiBaseUrl: "http://127.0.0.1:8080"
};
```

5. 开发者工具选择导入项目，目录指向`D:\demo_series\campus-pi\miniprogram`，核对AppID后编译。目录是miniprogram，不是frontend，也不是整个仓库。小程序原生结构不需要执行Vue的npm run dev。
6. 仅本机HTTP调试时，可在开发者工具的本地设置中启用“不校验合法域名、web-view域名、TLS版本及HTTPS证书”。这只用于本机开发者工具，不能作为上线配置，也不要修改共享模板中的URL校验默认值。
7. 保持8080后端运行，用校园Π普通账号密码登录。当前设计是先账号密码登录，再主动绑定微信；未配置后端AppSecret时不演示真实微信换码。

`apiBaseUrl`供手机使用，`devtoolsApiBaseUrl`供电脑开发者工具使用。手机的127.0.0.1指向手机自身，不能填成电脑后端。手机端地址留空会显示“服务地址尚未配置”。真机需要可访问的服务地址和微信合法域名；当前后端默认只监听127.0.0.1，文件地址还要求可信HTTPS或本机回环，因此仅把地址换成局域网IP不足以完成真机部署。完整说明见[小程序README](../../miniprogram/README.md)。

真实微信换码、完整真机链路与正式HTTPS部署仍待验收。本文的本机Web或工具模拟器启动成功，不代表上述能力已完成。

## 七 首次运行后如何检查

1. 在管理端以`admin / 123456`登录，确认能打开用户管理、分类、任务及通知页面。
2. 在用户端注册一个普通账号，修改资料、查看通知偏好并退出重新登录。刷新页面或冷启动后当前实现需要重新登录。
3. 分类应能看到初始记录；商品、帖子、任务和订单列表初始为空，不能把空列表视为后端故障。
4. 要测试发布与任务履约，先用实际页面提交实名及“本地测试校区”认证，再在后台审核。未配置扫描器时先完成文件配置。
5. 初始积分余额为0，不能直接发布需冻结积分的任务，不能通过注册或刷新自动加分。如需完整演示数据，另按[人工验收手册](../../database/manual/README.md)安装到专用`campus_pi_manual_test`库，不把人工资金导入本文数据库。
6. 页面逐项操作见[页面测试使用手册](../verification/校园Π页面测试使用手册.md)。图表仍使用JSON模拟数据；真实支付退款、短信找回等未接通能力不计为本地配置成功。

## 八 常见问题

|现象|优先检查|
|---|---|
|提示数据库已存在|停止首次初始化，核实原库；已有环境使用迁移，不删库或强制重跑|
|启动后数据库连不上|MySQL服务、端口、专用账户、密码及外部配置是否加载；启动日志并不自动证明数据库已接通|
|账号服务未完成本地配置|idempotency-secret是否仍为空，外部配置文件路径是否正确|
|admin / 123456无法登录|是否用了本文SQL建立的库；是否保留local-short-password-admin-id:1。此口令不是任意旧库的通用账号|
|管理职责未授权|管理员ID是否与duties-json中的1一致；普通USER不能靠配置获取ADMIN身份|
|正式校区名单尚未配置|allowed-campuses-json是否加载；申请名称是否与允许名单完全一致|
|通知不投递或批量一直待执行|相应worker是否启用；通知关闭和免打扰偏好也会影响投递|
|上传报扫描未配置或失败|实际MpCmdRun.exe路径、Defender状态及文件类型，不能使用假扫描结果替代|
|5173页面接口报错|8080后端是否运行、Vite代理目标是否正确；不要将小程序API写成5173|
|打包失败并提示JAR被占用|停止当前使用该JAR的本项目服务，再打包；其他Java应用保持不动|
|小程序提示服务地址尚未配置|运行平台与所选apiBaseUrl/devtoolsApiBaseUrl；工具编译后重新预览，不把电脑127.0.0.1给手机用|

维护初始化SQL时，修改原结构或追加迁移后运行`python scripts/build_local_init_sql.py`重新生成，再运行`--check`核对。只有重新生成时需要安装`scripts/requirements-auth-local.txt`中的Python依赖；普通使用者直接导入已生成SQL即可。不要手工维护一份精简表结构而遗漏后端需要的会话、文件或队列表。
