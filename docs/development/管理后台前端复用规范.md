# 管理后台前端复用与尺寸规范

更新：2026-10-22。依据本次“页面大小缩放不一致，尽量使用可复用组件”的要求，后台统一使用稳定的公共布局；保留Word报告的配色和业务结构，图表区域按可用宽度重排。此前整页随图片比例缩放的验收方式改为公共布局与响应式验收。

## 现有可复用部分

|内容|唯一实现|已接入及使用方式|
|---|---|---|
|侧栏、品牌、页头、搜索占位、用户返回、退出、窄屏导航|[WorkspaceLayout.vue](../../frontend/src/admin/WorkspaceLayout.vue)|App统一包裹后台页面，页面主体通过默认插槽显示；分析页不再单独改变侧栏和页头|

|列表标题、记录数、操作区|[AdminPageHeader.vue](../../frontend/src/admin/AdminPageHeader.vue)|用户列表和内容、认证权限、任务、订单举报、通知五个业务面板共同使用；操作按钮通过actions插槽传入|
|上一页、下一页、边界禁用、总数和每页条数|[AdminPagination.vue](../../frontend/src/admin/AdminPagination.vue)|上述六处共同使用；发出turn和size事件，由原业务面板加载实际数据。总数比较使用BigInt|

|表格、筛选栏、页签、按钮、状态、弹窗|[admin-ui.css](../../frontend/src/admin/admin-ui.css)|通过admin-filters、admin-table-scroll、admin-tabs、admin-dialog等公共类复用；由main.js统一加载|
|公共尺寸、颜色和窄屏行为|[workspace.css](../../frontend/src/admin/workspace.css)|统一控制导航和内容容器；业务页面不覆盖侧栏宽度、页头高度和公共字号|

不同业务表格的列、权限、确认操作和请求逻辑仍由原业务面板负责。通用交互已有组件就直接使用；只有样式相同的结构复用公共类，避免为每个div再包一层组件。

## 尺寸与响应式

|位置|公共规则|
|---|---|
|桌面侧栏|固定240px，导航文字14px、图标20px；不随页面、窗口高度和宽度缩放|
|页头|固定64px，桌面标题20px；450px以下标题18px|
|列表正文及表头|14px；表头44px、普通单行记录56px，长内容可自然增高|
|常用筛选框、操作按钮|36px；表格行内操作使用28px最小高度|
|内容间距|24px；900px以下16px，450px以下12px|
|窄屏导航|900px及以下通过页头按钮打开同一侧栏；关闭时inert，选择入口自动关闭，Escape关闭并返回按钮焦点|
|宽表格|在表格自己的容器内横向滚动，不撑宽整个页面|
|分析页|桌面图表使用固定可读字号；内容容器1100px以下指标与底部图表改为两列，900px以下底部图表改为单列；650px以下沿用移动图表布局|
|窗口高度不足|内容正常向下滚动；不为了把全部图表塞进首屏而缩小全站导航与文字|

## 新面板接入示例

在App既有WorkspaceLayout插槽内接入面板即可。面板复用公共结构，以下事件连接到自己的查询逻辑：

```vue
<script setup>
import AdminPageHeader from './AdminPageHeader.vue'
import AdminPagination from './AdminPagination.vue'
// page、total、loading、busy、load、turn由当前业务面板维护。
</script>

<template>
  <section class="admin-content-panel" :aria-busy="loading">
    <AdminPageHeader title="业务列表" :subtitle="`共 ${total} 条记录`">
      <template #actions>
        <button :disabled="loading || busy" @click="load">刷新</button>
      </template>
    </AdminPageHeader>
    <form class="admin-filters" @submit.prevent="load">
      <!-- 放置本业务的筛选字段 -->
    </form>
    <div class="admin-table-scroll">
      <!-- 放置本业务的表头、记录与操作 -->
    </div>
    <AdminPagination :page="page" :total="total"
      :disabled="loading || busy" @turn="turn" />
  </section>
</template>
```

分页默认每页20条。用户列表传入pageSize和pageSizes，保留10/20/50条切换；turn事件值为-1或1，业务面板统一处理请求、失败反馈与加载状态。其他面板不再各自维护重复的页数边界模板。

## 实际验证

- 8080打包应用公共布局134项通过：九个主页面在1918×944、1280×800、2560×1440下尺寸一致、复用同一个布局实例、没有页面横向溢出；五个次级入口也使用公共布局。
- 同宽1920px分别改变窗口高度，侧栏和字号不变；768/390/320px验证同一导航的展开、路由切换、关闭、Escape及焦点。实际用户列表验证20条切换、下一页、上一页和第一页边界。
- 模拟分析57项、页面入口50项和账号浏览器19项通过。原“730×547整屏等比”及“宽屏全部图表首屏显示”断言已按本次明确要求替换为公共尺寸、图表比例与正常滚动检查。
- 公共组件接入后，内容HTTP51/浏览器14、认证权限106/15、任务86/20、订单举报83/22、通知实际发布收件浏览器24均通过。随后仅调整公共CSS装载、控件尺寸和复用plus图标，再次打包并通过布局134、分析57及入口50检查。
- 订单HTTP回归曾因累计测试数据超过第一页，找不到随机编号的合成售后工单；脚本已通过真实分页定位工单后继续核对材料与金额，83项通过。该修复没有改变业务排序或删除既有记录。

私有截图与机器结果位于被忽略的 `.local/auth-dev/admin-layout/`。布局验收不等于原报告全部业务完成；原有全局搜索等占位入口和JSON模拟统计的实现边界保持原样。
