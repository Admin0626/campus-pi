## 复用与实现方式

Web 用户业务使用 `frontend/src/member/`：统一导航 `MobileTabs`、操作和分页组合函数、状态提示、分页、字段表单、文件上传；产品、帖子、任务、订单、争议、私信和认证各有业务组件。文件查看复用已有管理端 `FilePreview`，未重新维护第二套授权预览逻辑。首页和个人页读取真实列表及本人统计，删除“已接通业务仍显示开发中”的入口。

原生小程序使用 `services/business.js`、`business-surface` 和 `protected-files`；列表、详情、输入、上传、分页、错误及任务凭证记录共用组件，发现、私信和业务入口复用同一实现。账号导航和会话仍使用此前公共服务层。资料编辑与头像保存已由 Web 和 API007 提供；由于本机微信类型定义未列出 PATCH、实际工具操作超时，原生资料页暂明确只读，未悄悄改动原接口或将 Node 适配器通过当作微信方法兼容证明。

后端 `member` 包复用账号鉴权、文件授权、业务编号及任务状态渲染。事务中重新验证资格并加锁，幂等键按操作和请求内容校验。审核通知复用既有偏好与 outbox，审核回滚则通知一并回滚；不会给审核员额外的任意通知发布职责。原 SQL 存储过程作为设计基线保留，业务采用等价服务事务，未在自提交存储过程外叠加事务。

## 验收入口和复跑

1. 打包后的本机入口为 `/login`、`/admin/login`。普通用户在“个人”进入认证、商品、帖子、任务、订单；底栏进入发现、发布和私信，右上角进入通知。管理端继续审核同一批真实业务对象。
2. Web 用户页需要真实账户；发布商品/任务前完成实名及校园认证。新账户积分为零，不会开放自行改余额按钮。测试夹具不能用作正式资金来源。
3. 先运行 `python scripts/prepare_member_acceptance.py`，只建立本轮合成账号、通过真实材料审核，并明确给新建测试发布者分配100测试积分。随后 `node scripts/check_member_browser.cjs` 和 `node scripts/check_member_native_adapter.cjs` 需要被忽略目录中的新建合成验收账号；脚本明确注明范围，不在仓库提供共享口令。
4. 普通构建使用 Java17、`npm ci`、`npm run build`、`mvn -B clean verify`。集成测试显式启用 `CAMPUS_MEMBER_INTEGRATION=true`、`CAMPUS_WECHAT_INTEGRATION=true`，并验证隔离库的端口、schema 和数据目录；不能指向共享/生产库。
5. `.github/workflows/verify.yml` 在 GitHub 临时服务中从空库执行相同初始化和集成检查。没有依赖本机 `.local` 密钥，也不会连接校园共享库。

本轮保留在本机 `wlky`，不合并 `main`，不自动部署。项目尚不能按“已全部上线/原生已完整验收”结项。
