## 修复顺序

1. 固定原始文件指纹，提取正文、45项数据字典、原有SQL和全部嵌入图片，核对问题位置。
2. 统一登录、权限、任务状态、两类订单、奖励和通知规则，再建立字段与数据流映射。
3. 按依赖顺序重建MySQL设计：25张表，配套12个核心存储过程、4个触发器。补齐主外键、唯一约束、值域和金额检查。
4. 在独立MySQL 8.0.44实例中创建专用合成测试库，执行正常、异常、回滚、幂等和并发用例；密码哈希使用独立Argon2id参考库验证。
5. 将同一模型写回报告，修正数据字典和处理说明，重绘受影响的流程、逻辑和界面图，替换过期数据库截图，更新目录和页码。
6. 导出并逐页检查报告和修复记录；检查源文件未变化。关闭独立测试实例并删除其中的专用测试数据库，不触及原有MySQL服务或业务库。

## 统一设计决定

- 登录采用账号与密码，账号支持用户名、手机号或邮箱。短信登录和第三方登录保留为扩展规划，常规登录不同时强制多套凭证。
- 一张订单只对应一种商品或一个任务；商品数量可大于1，任务订单数量固定1。跨商品合单不在本版范围。
- 任务统一八种状态。接取申请不改变任务的待接取状态，管理员分配成功后进入进行中；凭证待审时为待验收。
- 验收要求补充凭证返回进行中，保留旧版本；未完成任务只能由管理员终止并退回未结算奖励。本版不支持将进行中任务直接重新分配。
- 账本内现金仅表示金额与一致性模型，所有验证使用合成余额。真实充值、支付、提现和退款尚未接入。
- 文本字段长度按字符标识；BIGINT／INT的存储长度与DECIMAL的数值精度分开表述。
- 推荐、信誉评分、点赞评论多媒体、活动报名、匿名私信、画像、DAU留存与智能预警明确列为扩展规划，现有原型占位不作为已完成能力。

## 如何使用交付文件

报告修订版是本次设计基线。01_数据库结构.sql及02_核心业务事务.sql用于新建MySQL 8.0.16以上空库；本次使用8.0.44验证。两份脚本均不包含删除现有表的操作，不能作为已有数据库的自动迁移脚本。

如需重跑验收，在新建空库依次执行01和02后，安装requirements.txt，使用本机MySQL客户端和一个私有的客户端配置文件运行：

```text
python 04_自动验收.py --mysql-exe <mysql客户端绝对路径> --defaults-file <私有客户端配置文件绝对路径> --database <新的测试库名>
```

配置文件采用MySQL客户端格式，包含host、port、user、password等字段。不要把真实密码写入命令行、提交到仓库或放进交付包。程序要求业务表为空，自行生成并载入合成数据；不要先执行03_合成测试数据.sql。03仅供手动查看数据结构。自动验收不创建或删除数据库；测试后由使用者确认目标并清理测试库。

自动验收需要创建存储过程的权限以安装02脚本，但运行用例只调用已创建对象。本次原有数据库和原有MySQL服务未改变。交付包不包含数据库连接密码、私有认证材料或真实用户数据。
