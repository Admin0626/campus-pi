# 校园Π人工测试数据手册

普通部署只使用[database/init.sql](../../database/init.sql)。人工验收数据为可选材料，不再把生成的SQL、矩阵及图片重复放进GitHub。

## 按需生成测试材料

在仓库根目录运行：

```powershell
python -m pip install -r scripts/requirements-auth-local.txt
python scripts/build_manual_test_sql.py
```

输出全部位于被Git忽略的`.local/manual-test/generated/`：

|输出|用途|
|---|---|
|校园Π全功能人工测试.sql|13个合成账号、业务历史与初始状态、图片内容及117条用例|
|接口人工测试矩阵.json|111个有效接口和6个补充/退役检查的人工预期|
|上传样例/ 下4张PNG|商品、头像、凭证和认证材料的真实上传测试输入|

生成器只写本地文件，不连接数据库。按需产物不代表用例已经通过；合成付款、积分和扫描历史不代表真实资金或真实扫描。全部材料可以从同一生成器重复生成，不需要提交副本。

## 安装到独立测试库

连接配置仅保存在`.local/manual-test/database-private.json`：

```json
{"host":"127.0.0.1","port":33321,"user":"root","password":"替换成本机测试库密码","database":"campus_pi_manual_test"}
```

```powershell
python scripts/prepare_manual_test.py --config .local/manual-test/database-private.json
```

安装器会先生成本地测试资料，只对指定的本机专用库操作。空库按`database/schema.sql`及V001–V009安装完整结构，再导入生成的测试SQL、还原25张附件并生成私有服务配置。有现有用户则拒绝导入，不覆盖旧数据或图片；无需重导正在使用的测试库。

手动执行时同样只使用独立新空库：先运行schema.sql和按编号排列的全部迁移，再运行生成的整段测试SQL；客户端须支持DELIMITER并遇错停止。只导入SQL不会还原附件文件，推荐使用安装器。

## 测试入口与操作

- 已安装后的用户端：<http://127.0.0.1:8082/login>；管理端：<http://127.0.0.1:8082/admin/login>。
- 页面步骤见[页面测试使用手册](校园Π页面测试使用手册.md)。上传时在文件选择框打开`.local/manual-test/generated/上传样例/`。
- 服务运行状态须实际核对。8082仅为本机人工验收环境，普通部署无需开启第二套服务。
- 测试通知worker默认关闭，批量worker开启；需要观察到期实际投递时，在测试私有配置中开启通知worker并重启。

## 推荐人工测试顺序

每个操作记录页面、账号、对象 ID、请求/响应、预期、实际及数据库变化。写接口依现有契约提供 `Idempotency-Key`；同键同内容重放不重复写入，同键不同内容应冲突。表中“历史”状态只能测试查询展示；完整状态转换必须新建对象通过实际接口执行。

|顺序 / 模块|现成数据与入口|实际操作与预期|
|---|---|---|
|1 / A 账号|上表账号，登录、个人资料、用户管理|普通/管理员登录，停用登录被拒；用 `manual_password` 改密并验证旧会话失效；Web 修改资料和头像；按用户 ID、用户名、注册日期搜索，显示真实最近登录时间|
|2 / B 认证和文件|认证 900001 待实名审、900002 待校园审、900004 已驳回|使用管理员审核；用户查看结果；新上传实际图片测试扫描、授权预览、无权限访问拒绝。历史图片的 `TEST_FIXTURE` 标记不等于真实杀毒通过|
|3 / C 商品|商品 900001–900009，分类 900001/900002 及子类 900011–900013、空类 900099|浏览、分类筛选、图片预览、收藏/取消；900002 可审核；新建商品、修改重新审核、上下架；900006 只有 1 件，可验证竞争下单不超卖；停用卖家的 900007 不公开|
|4 / D 帖子|MANUAL_POST_1–6 覆盖公开、待审、匿名、驳回、下架、删除|查看匿名投影不泄漏作者；脚本文字按文字渲染；新建、审核、编辑重审、收藏及删除，失效收藏不当成公开帖子|
|5 / E 发布与申请|任务 900001 待审、900002 待接取；申请 900001/900002 待审|先审发布，再用两用户申请并只分配一人；撤回申请后不能再次申请同一任务；用零余额账号验证冻结失败，取消符合条件的任务会解冻|
|6 / F 凭证与结算|任务 900003 进行中；900004 待验收；900009 补证；900010 第二版待审|实际接取者上传新凭证，非接取者拒绝；补充凭证产生新版本；验收通过只结算一次并增加接取者积分；失败任务 900006 在关闭时释放冻结；全局审核记录按任务/关键词/日期筛选|
|7 / G 订单和争议|商品订单 ORDER26010190000001–8；任务订单 ORDER26010191000003/4/5/6/9/10|实际预约线下订单、卖方交付、买方收货与交付前取消；任务零金额争议新建/撤回/管理审核；AFTER26010190000001–5 提供查询状态。商品历史支付/退款仅用于展示；线上支付路由已删除，商品退换及款项问题线下协商|
|8 / H 私信和举报|会话 900001 卖方/买方、900002 卖方/同校同学；消息 900001–900013|查看、实际发文字和图片、游标分页、未读/已读、单侧删除；聊天输入区保持可见，切换会话不残留消息；第三人不能读取；举报及本人记录和管理审核|
|9 / I 通知|MANUAL_DRAFT、MANUAL_NOTICE_SENT、MANUAL_NOTICE_REVOKED、MANUAL_NOTICE_WAIT；投递 900001–4|编辑草稿、预览/确认发布、撤回；收件阅读与偏好；关闭不接收，免打扰后投递，安全通知同样遵守；全局投递记录可筛选；失败项重试不重复产生收件，撤回投递不能重试|
|10 / 管理批量|历史批次 `3b66da22-90f5-50f2-bd8b-2c28ed283658`，商品部分成功/失败|四类批量均使用新待审对象和独立测试用户；故意提前改变一条状态；保留成功并列出失败，再仅重试失败；默认收起结果不遮住主表，操作列持续可见|
|11 / 布局与控制台|首页、用户模块、控制台、数据分析|320/390 手机宽和 1280/1918 桌面宽；底栏、聊天输入、图片、复选框、后台操作列不溢出；控制台真实指标与标为 JSON 模拟的图表区分，数据分析仍用原组件|

预置卖方积分可用 840、冻结 140，接取者可用 20；历史总额来自夹具分配，不代表实现充值/赠送。任务 900011 的现金数据只供关闭能力的边界测试，不是真实资金。日期筛选按北京时间自然日，夹具时间多为 2026-10-20，测试时注意不是今天。

## 尚不能以本数据代替的验收

- API004/005（找回/短信）仍有外部依赖；API050/051已用于线下交付、收货，API052已删除并返回404。API053/099仅任务零金额争议可用；商品退换及款项问题线下协商。具体以矩阵及当前接口说明为准。
- 真实微信换码、支付、短信、正式扫描、HTTPS、生产迁移和真机链路需要各自真实环境；没有种入微信身份或真实会话 token。
- 原生资料编辑已获准使用 PUT /me 兼容入口，与原 PATCH 共用校验和事务；真实渲染/真机仍需独立验收。
- 信用分、推荐、活动、多媒体帖子、全局搜索、系统设置等尚未定义范围与规则；不能把占位或历史数据记为实现。

## 校验与复测

主 SQL 最后 4 条断言的 `passed` 均应为 1。额外可执行：

```powershell
python scripts/check_manual_test.py --config .local/manual-test/database-private.json
```

校验器验证专用 schema、初始数据、图片 SHA、用例矩阵、重复装载保护，以及 8082 上实际登录、查询和权限。它只创建短期会话，不消费业务夹具；人工操作后初始状态断言可能变化，此时应根据自己的操作记录判断，不能重导覆盖数据。需要从头测试时，另行备份并由负责人选择清理专用库；本工具不自动删除数据库。

如需重启本机测试服务，使用 Java17，先构建前端及后端，再在仓库根目录执行（私有配置需已生成）：

```powershell
java -jar backend/target/campus-pi-server-0.0.1-SNAPSHOT.jar --spring.config.additional-location=file:./.local/manual-test/application-local.yml
```

正式环境仍使用原迁移和最小权限配置，不装入这套测试口令、历史资金或合成扫描记录。

## 线下交易用例

已有库先执行V009，不能重新导入整套种子。新建测试库可使用更新后的SQL：ORDER26010190000009待线下交易、ORDER26010190000010待确认收货、ORDER26010190000011已完成、ORDER26010190000012已取消。API050由manual_seller确认交付，API051由manual_buyer确认收货；旧付款/退款快照只用于历史展示。复测闭环应从商品新建订单，避免反复消费同一夹具。
