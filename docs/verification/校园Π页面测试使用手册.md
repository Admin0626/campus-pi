# 校园Π页面测试使用手册

版本：2026-10-23。适用对象：负责人工验收的同学。本文按当前可运行页面说明“从哪里进入、点击什么、填写什么、应该看到什么”。数据库安装和接口用例另见[测试数据手册](../../database/manual/README.md)与[接口测试矩阵](../../database/manual/接口人工测试矩阵.json)。

## 1. 第一次使用：先完成这五步

1. 打开用户登录页：<http://127.0.0.1:8082/login>。输入 `manual_buyer` 和 `CampusPi!2026`，点击“登录”。
2. 登录后应进入“校园生活”首页。底部有“首页、发现、发布、私信、个人”。先点击“个人”，确认当前用户名是 `manual_buyer`。
3. 另开一个独立窗口，例如无痕窗口，打开管理登录页：<http://127.0.0.1:8082/admin/login>。输入 `admin` 和 `123456`，点击“登录”。
4. 管理端应进入控制台，左侧有内容发布管理、用户管理、交易管理、悬赏任务、订单管理等菜单。接下来的双角色测试分别使用这两个窗口。
5. 上传文件时，直接使用[上传样例文件夹](../../database/manual/上传样例/)内的四张 PNG：测试商品、测试头像、测试凭证、测试认证材料。也可在文件选择框中进入 `D:\demo_series\campus-pi\database\manual\上传样例`。

**当前登录凭证只保存在页面内存中。按 F5、关闭页面或在地址栏重新打开页面后，需要重新登录；“记住登录状态”尚未实现。** 登录以后请使用页面按钮、底部导航或侧边菜单进入业务页面。下面的“路径”用于辨认和记录页面，不能代替登录后的按钮操作。

本文全部 Web 操作使用 **8082 人工测试环境**。8080 是另一套日常开发环境，其账号和数据不保证相同。下面的 `127.0.0.1` 地址只能在运行后端的这台电脑上使用。

### 1.1 操作约定

- 等“正在加载”“正在上传与安全扫描”等提示结束后，再继续操作。
- 大多数详情、发布表单、审核表单和页签共用父页面地址，没有独立网址；进入方法是点对应按钮。
- 新建内容统一命名为 `手测_姓名_日期_序号`，例如 `手测_小吴_1023_01`，避免九位同学互相覆盖或误认记录。
- 审核、改密、禁用、撤回和删除会改变测试数据。固定数据被别人处理过时，先看当前状态，再使用自己新建的记录测试，不能反复对同一条记录期待相同按钮。
- “重置”通常只清空查询条件，不恢复数据库初始状态。不要反复导入 SQL；已有用户的人工库会拒绝覆盖。
- 看到明确的“尚未接入”“还在开发”，按第7节记录为未开放，不填写“功能通过”。

## 4. 用户端逐页操作

### U01 登录、注册、找回入口

**登录：**在 `/login` 填写用户名和密码，点“登录”，核对进入首页及“个人”显示的用户名。输入错误密码应提示失败；`manual_disabled` 应被拒绝。

**注册：**登录页点“立即注册”，填写未使用的用户名（字母开头，3–25位字母/数字/下划线）、邮箱或手机号至少一项，以及12–64字符密码。建议邮箱使用 `你的测试用户名@example.invalid`，手机号留空。点“提交注册”，应返回登录页；再用新账号登录。新账号未认证、积分为零，需要继续认证，不能直接当成已认证卖家。

**找回：**登录页点“忘记密码?”，查看未接通说明，再用“返回登录”返回。手机验证码、用户协议、第三方登录和记住登录状态等占位入口不能作为本轮登录成功路径。

### U02 首页、发布选择和个人中心

1. 首页点“二手交易”查看商品；点“悬赏任务”查看任务；点“热门信息”的“查看更多”查看帖子。
2. 底部点“发布”，选择“二手商品”“校园帖子”或“悬赏任务”，进入对应模块后再点“发布商品”“发布帖子”或“发布任务”。类型选择本身不等于已提交内容。
3. 底部点“个人”，查看认证状态和发布商品/帖子/任务的真实数量。
4. “我的服务”进入发布、收藏、订单、任务记录；“设置”进入认证、账号设置、通知中心、修改密码。

**预期：**入口可进入对应模块；“学号：—”表示本人接口未提供该字段，不代表登录失败。

### U03 资料、头像和隐私

账号：`manual_buyer`，入口：“个人 → 账号设置”。

1. 在“上传图片”中选择 `测试头像.png`，等待扫描和预览完成。头像最多一个；选错时先点“移除”再重选。
2. 填“个人介绍”，例如 `手测_小吴_1023_资料`；填“默认地址”，例如 `测试校区图书馆门口`。
3. 切换“公开所在校区”“公开个人介绍”，点“保存资料”。用户名不能在此修改。
4. 回到“个人”，再通过“账号设置”进入，检查刚才的介绍、地址和开关；核对头像。

**预期：**保存后显示本人最新资料；地址只供本人使用。头像选文件后还须点击“保存资料”，仅有上传预览不等于资料已保存。

### U04 修改密码

账号：只用 `manual_password`，入口：“个人 → 隐私安全”。

1. 填当前密码 `CampusPi!2026`。
2. 新密码和确认密码填相同的12–64字符测试口令，例如 `CampusPi!2026_New`。
3. 点“确认修改密码”，应要求重新登录。
4. 用新密码登录成功；旧密码登录应失败，原会话不能继续使用。记录新口令供后续同学识别，避免误认为初始账号损坏。

### U05 实名和校园认证

入口：“个人 → 实名与校园认证”。新提交用 `manual_unverified` 或新注册账号；查看已有校园待审用 `manual_campus_pending`。

1. 点击“提交认证”，认证类型选“实名”，填虚构测试姓名，选择 `测试认证材料.png`，等上传完成后点“提交”。
2. 本页查看新记录，应为“待审核”。若固定账号已有待审核申请，先由管理员处理该申请，再提交新申请。
3. 管理员按 M03 审核后，用户重新进入认证页查看“已通过”或“已驳回”和原因。
4. 实名通过后再次点“提交认证”，类型选“校园”，填同一个测试姓名、校区 `测试校区`、未使用过的测试学号，例如 `MUI1023_01`，上传测试材料后提交。
5. 管理员通过校园认证后，重新登录或重新进入个人页确认状态与校区，再测试发布商品/任务。

**预期：**先实名后校园；校区必须符合本机名单，学号不能抢占其他已认证账号。样例只是独立测试环境的图形图片，不是实际身份材料。认证记录和材料只有本人或具相应职责的管理员可查看。

### U06 商品浏览、收藏和联系卖家

账号：`manual_buyer`；入口：“首页 → 二手交易”。固定数据可找商品 `900001`，名称“人工测试-在售教材”。

1. 在“在售商品”中用名称搜索，或选择商品分类。
2. 点“查看商品”，检查图片、售价、库存、校区、描述和卖家。
3. 点“收藏”，回列表切到“我的收藏”，应能找到该商品；再次点“取消收藏”后应移除。
4. 商品详情点“联系卖家”，进入与 `manual_seller` 的私信；按 U12 发送消息。

**预期：**待审核/驳回/下架商品不作为在售公开内容显示，停用卖家的公开商品被隐藏。自己的商品详情显示编辑/上下架操作，其他人的商品显示收藏、联系和购买。

### U07 商品发布、编辑和上下架

账号：`manual_seller`；入口：商品页“发布商品”。

1. 选择 `测试商品.png`，等待上传完成。
2. 选一个已有分类，名称填 `手测_姓名_1023_商品01`，填写描述；认证校区使用账号已有值。
3. 交易方式选“校园自提”，自提位置填 `测试校区图书馆门口`，原价填 `25.00`、售价填 `20.00`、库存填 `2`。
4. 点“提交审核”。到“我的发布”查看，应为“待审核”。
5. 管理员按 M02 通过审核后，换买家在在售列表找该名称。
6. 卖家从“我的发布 → 查看商品 → 编辑并重新审核”修改描述，确认图片仍满足表单要求后再次提交；状态应重新待审核。
7. 再通过审核后测试“下架”，买家应不能继续在公开列表查看；满足当前状态规则时可“上架”。

**预期：**不接受冒用其他人的上传引用；存在未结束订单时编辑可能被拒绝，属于状态保护。为避免干扰 U08，先完成编辑/上下架测试，再创建订单。

### U08 线下商品订单、交付、收货与取消

使用U07创建并审核通过的在售商品。买卖双方在不同浏览器窗口登录，避免身份串用。

1. `manual_buyer`打开“查看商品 → 预约线下交易”，填写数量1、自提交接地点，点击“确认创建线下订单”。进入我的订单后应显示“待线下交易”和约定金额，记下订单号。
2. 买卖双方通过“私信”约定自提时间和地点；实际交易时当面验货并自行结算，平台不收款。
3. `manual_seller`打开“我的订单 → 卖出”，找到该订单，点击“确认已线下交付”并确认，进入“待确认收货”。此时不可再取消或返还库存。
4. `manual_buyer`重新打开订单，点击“确认已线下收货”并确认，进入“已完成”，显示完成时间。
5. 另建一张线下订单，在卖家尚未确认交付时由买方点击“取消订单”。应取消并恢复一次库存；重复新请求不能重复释放。

**预期：**金额为服务端商品价格快照；卖家不能代买家收货，买家不能提前收货，其他用户不可读写订单。线下订单不生成平台支付时间、流水或实收金额。商品退换及款项问题由双方线下协商。商品的历史付款状态仅用于保留旧记录，不开放付款按钮。

### U09 帖子浏览、发布、匿名和删除

入口：底部“发现”。发布用 `manual_seller`，查看用 `manual_buyer`。

1. “校园广场”可搜索标题，点“阅读全文”进入详情。
2. 点“发布帖子”，选分类，标题填 `手测_姓名_1023_帖子01`，内容填测试文字。可勾“匿名发布”。
3. 点“提交审核”，切“我的发布”查看待审记录；管理员按 M02 的“帖子信息审核”处理。
4. 买家搜索已通过帖子，检查全文、时间和作者显示。匿名帖对其他人应隐藏真实作者；纯文本中的 `<script>测试文字</script>` 应按字面显示。
5. 买家点“收藏”，在“我的收藏”查看；取消收藏后移除。
6. 发布者在“我的发布 → 阅读全文”中点“编辑并重新审核”，提交后重新待审；点“删除”则按提示确认，公开列表及有效收藏不再显示。

**预期：**当前帖子编辑器只支持纯文本，不测试图片、视频、点赞或评论。固定匿名历史记录为 `MANUAL_POST_3`。

### U10 任务发布、申请和分配

发布者：`manual_seller`；申请人：`manual_buyer`、`manual_peer`。入口：“首页 → 悬赏任务”。

1. 发布者点“发布任务”，填名称 `手测_姓名_1023_任务01`，说明填 `领取测试资料并上传完成凭证`，奖励类型“积分”、奖励积分 `20.00`，提交。
2. 查看可用/冻结积分及“我发布的”。应新增待审核任务，可用积分减少20、冻结增加20。
3. 管理员按 M05 通过发布审核，记录管理列表中的任务ID。

3. 等待批次结果。点击“批次已完成：成功…失败…”展开，逐条核对；默认收起不代表没有执行。
4. 验证部分失败：在第二个管理窗口先处理其中一条已选记录，再在原窗口提交批量。应保留其他成功项，并列出该条冲突，不回滚全部。
5. 点“只重试失败项”时，确认对话框只列失败ID；不满足状态的条目再次失败属于正确边界。可用“查询最近批次”和下拉框查看历史。

### M13 数据分析与未开放管理页面

1. 左侧“数据分析”，切“本周/本月/本季度”查看指标；趋势图另有“周/月/年”，两组切换含义不同。
2. 鼠标移到折线点查看提示，点击饼图/环图分类或图例检查选中状态。
3. 在交易类型占比卡右上“⋮”打开“数据分析操作”，可刷新模拟数据、导出CSV、查看模拟数据明细；其他图表的“⋮”也可查看对应明细。
4. 分别在1280×800、1918×944和手机320/390宽查看，检查图例不重叠、页面不横向溢出，管理导航尺寸一致。
5. “系统设置”进入开发中说明；顶部“全局搜索”“帮助”，用户列表的反馈/新增/编辑等按提示记录为未开放。不能为这些入口填写业务操作成功。

## 6. 通知实际收件的准备

8082 人工环境默认关闭通知投递worker，目的是保留预置“待发送/失败/免打扰”数据。此时可验收草稿、发布任务建立、查询、撤回和偏好保存；**不能期待新通知自动送达。** 批量操作worker是开启的，不受此限制。

需要跑 M10 → U14 的实际收件流程时，由维护者先停止当前8082服务，在仓库根目录使用 Java17 按下列命令启动（本机私有配置须已准备）：

```powershell
java -jar backend/target/campus-pi-server-0.0.1-SNAPSHOT.jar --spring.config.additional-location=file:./.local/manual-test/application-local.yml --campus.notifications.worker-enabled=true
```

不要在旧8082进程仍占用端口时再开一个同端口实例。启用后，现有到期队列也可能开始执行，先完成固定数据查看和截图。之后用指定用户900004测试正常收件、900008测试关闭不接收、900009测试免打扰。修改免打扰做短时间测试后应恢复并记录；安全类型也遵守这些偏好。

## 7. 小程序如何进入和操作

这一节用于已有微信开发者工具运行环境的同学。当前已有独立编译和组件方法联调证据，**真实微信渲染、完整导航及真机尚未验收**，不能只读本手册就记通过。

1. 开发者工具导入仓库 `miniprogram` 目录，使用本机私有项目配置中的AppID。不得把AppSecret写进小程序。
2. 要复用本文13个账号，由维护者把被忽略的 `miniprogram/config.js` 中 `devtoolsApiBaseUrl` 指向 `http://127.0.0.1:8082`。如果仍连8080，则使用的是另一套开发库，不保证这些账号存在。
3. 编译运行后先用用户名和密码登录。冷启动后需重新登录。开发者工具本机HTTP与手机真机网络不同，真机不能使用手机自己的127.0.0.1连接电脑。

|小程序页面|入口及操作|
|---|---|
|首页 / 发现 / 发布 / 私信 / 个人|使用底部自定义导航；业务内容沿用公共组件|
|商品、帖子、任务|首页快捷入口或发布选择进入，按“在售商品/校园广场/任务广场”等标签切换，创建时“发布 / 申请”；列表卡片打开详情|
|资料与隐私|“个人 → 账号设置 → 编辑资料”，填写介绍、地址和公开开关，选择上传头像后点“确认提交”；使用PUT兼容入口保存|
|认证、订单、任务记录|“个人”中的对应入口；收藏标签在原生端可能显示为“收藏”|
|私信|“私信 → 新会话”输入对方用户ID，或打开已有会话；再发送文字/实际上传图片|
|通知与偏好|“个人 → 通知中心 → 通知偏好”；详情按原生显示操作，不把Web的“查看不自动记读”规则无条件套到原生实现|
|改密|“个人 → 隐私安全”，用独立改密账号测试|
|微信绑定|“个人 → 微信账号绑定”，先密码登录再主动绑定；人工库默认未配置真实微信，预期显示“微信登录尚未配置”。只有真实后端换码配置和微信权限齐备才能继续|

原生业务页按页面显示的“提交/返回/刷新”等按钮操作；不要将Web的“确认创建线下订单”等文字当成原生按钮的固定名称。绑定不自动注册校园账号，也不开放替换已有绑定关系。

## 8. 建议的验收顺序

|顺序|执行内容|建议记录|
|---|---|---|
|1|两个窗口分别用户/管理登录，浏览全部入口|角色、页面名称和地址|
|2|U03资料，U05认证与M03审核|表单输入、审核原因和状态|
|3|U07发布 → M02审核 → U06收藏 → U08下单取消|商品名称、管理列表ID、订单ID与库存变化|
|4|U09帖子 → M02审核 → 匿名/收藏/编辑/删除|标题、帖子ID和公开状态|
|5|U10任务 → M05发布/分配 → U11凭证 → M06验收|任务/申请/凭证ID、积分前后值和流水|
|6|U12私信举报 → M09处理；U13争议 → M08处理|会话、消息、举报或工单ID|
|7|准备worker，M10通知 → U14收件/偏好 → 撤回|通知ID、投递状态、读/点击时间|
|8|M12批量、M11权限拒绝和日志、M13图表布局|成功失败明细、拒绝提示和截图|
|9|最后用独立账号测试改密、启停用、角色变化|新口令由测试者自行保管、账号恢复情况|

先完成主流程，再做删除、取消、停用、改密等会改变后续入口的操作。对同一数据进行互斥分支测试时，分别创建记录，例如一个任务验收通过，另一个任务验收失败后关闭。

## 9. 遇到问题先这样检查

|现象|先检查什么|如何记录|
|---|---|---|
|8082页面打不开|服务和33321人工库是否启动，是否误用8080|时间、访问地址、浏览器错误|
|刷新后跳回登录|当前页面内存令牌不会跨刷新保存|重新登录再用按钮导航；按现有会话设计记录|
|固定账号密码失败|是否连接8082，是否被别人改密/禁用；连错环境不重导SQL|账号名和提示，口令不放截图|
|找不到预置记录|账号是否为买方/卖方、分页、状态/日期条件、是否已被别人处理|点重置、检查对应标签；初始数据多在2026-10-20|
|“我的收藏/发布”看起来不对|入口打开模块后是否切换了模块内标签|记录入口和标签名|
|任务没显示提交凭证按钮|是否实际接取者，任务是否进行中，申请是否已分配|任务ID、当前用户、任务/申请状态|
|审核按钮不见了|记录已审核、状态不允许或账号职责不足|记录现状，不重复套用初始预期|
|通知未到|worker开关、接收开关、免打扰、发送范围、撤回状态和投递失败原因|区分待发送、失败、关闭不接收和已经送达|
|上传失败或预览失效|实际PNG/JPEG/WebP、图片大小、扫描服务；头像不超过2MiB，一般图片不超过5MiB|保留提示；重新申请预览/上传，不手填file引用|
|订单没有线上付款按钮|商品采用线下交易|双方约定自提，卖家确认交付后由买家确认收货|
|积分与840/140不同|初始额只适用于未消费夹具；是否已发布、取消或完成任务|记录操作前后余额和流水，而非强行回填|
