## 可重复的验证方式

本次最终检查：设计基线通过；Java17构建和原404测试通过；真实HTTP **55项**通过；浏览器 **18项**通过；小程序宿主适配器 **14项**通过。后两者的证据范围分别限定为Web和Node适配器，未扩展为微信真机结论。JAR静态资源存在，且未打包本地配置或运行密钥。

随后补充的页面入口检查 **41项**通过：24个页面URL返回应用入口，所有当前用户端和管理端业务占位可到达，未登录后台入口跳转登录，认证与找回页面的未开放状态准确。5个原生WXML、1个公共WXSS通过本机官方独立编译器，生成JS语法检查通过。该结果不扩展为微信登录、授权域名或真机验收。

- Java 17 `mvn -B clean verify`：原安全404回归测试、编译与打包。这个单项JUnit测试不代表账号功能全面验收。
- `npm run build`：Vue打包；前端产物同时进入JAR静态资源。未修改原112项契约及其45项资产基线。
- `scripts/check_auth_http.py`：真实服务+独立MySQL，验证注册、查重、密码散列、零账户、幂等、并发重试、依赖失败回滚、权限、隐私、停用启用、改密、退出、绝对/闲置过期、失败限流与审计。
- `scripts/check_auth_browser.cjs`：真实浏览器操作，覆盖注册到登录、资料保存、改密、管理查询及状态变更、开发中占位和手机Web兼容；这不等于小程序验收。
- `scripts/check_miniprogram_adapter.cjs`：Node宿主适配器测试原生页面逻辑与真实HTTP；不验证WXML/WXSS引擎、微信域名策略或真机。
- `scripts/check_wechat_compile.py`：本机官方独立WXML/WXSS编译器接受5个页面与公共样式，生成JS语法通过；不等于带真实AppID的IDE运行。
- `scripts/check_page_entries.cjs`：逐个验证用户端、管理端的业务占位入口，以及登录、注册、账号和后台等URL直接访问；认证占位明确标注实名与校园认证。
- `scripts/check_baseline.py`：设计资产、112项接口归属、静态链接与25表基线；该检查与运行验收分开。

原始本地结果、截图与本机凭证分开保存在被忽略的`.local/auth-dev`。凭证不纳入本文件，不提交JAR、node_modules、数据库目录或本地配置。
