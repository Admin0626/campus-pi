- Windows 本机；JDK 17.0.12、Node.js 24.13.0、Spring Boot/Vue 项目锁定依赖；真实 Chrome/Playwright 访问打包后的 `127.0.0.1:8080`。

- 黑盒采用等价类、边界值、状态迁移、角色/对象访问矩阵、决策表、并发、重复请求及故障恢复；白盒采用控制流/数据流审查、事务和账本不变量、异步生命周期检查及 JaCoCo 覆盖测量。
- 产品缺陷与测试脚本问题分开登记。P1 表示可能破坏资金/状态一致性；P2 表示可见的上下文、分页或资源生命周期错误。没有用测试条数替代严重性判断。

## 6. 复跑与证据位置

在仓库根目录使用Java17、项目锁定的Node依赖以及已验证的隔离数据库；Python需安装本仓库测试依赖。集成测试须显式启用，否则跳过不能算通过：

```powershell
$env:CAMPUS_MEMBER_INTEGRATION='true'

npm --prefix frontend run build
mvn -B -f backend/pom.xml -Pcoverage clean verify
node --test scripts/check_frontend_whitebox.test.mjs scripts/check_native_whitebox.test.cjs scripts/check_analytics_data.test.mjs

python scripts/check_api_boundaries.py
python scripts/check_baseline.py
python scripts/check_shared_config.py
python scripts/check_frontend_package.py
```

HTTP/浏览器脚本需要正常打包服务、现有专用合成账号配置、可用Chrome/Playwright与真实文件扫描；它们不会自行启动后端。通知恢复测试另需在**自己的本机服务**中先关闭通知worker、执行 `--stage notification-off`，再使用相同私有配置重启启用worker、执行 `--stage notification-on`。普通运行未带agent时，不能把仅JUnit报告当作本轮聚合覆盖率。覆盖代理仅绑定本机临时端口，使用[JaCoCo dump](https://www.jacoco.org/jacoco/trunk/doc/dump-mojo.html)追加数据后生成报告。

共享保存本报告、计划、脱敏结果JSON和测试源码；原始日志、含会话的夹具及覆盖产物留在忽略目录，不写入AppID、AppSecret、令牌或共享密码。主要证据目录为 `.local/testing/`、`.local/auth-dev/`、`.local/remaining/`、`backend/target/surefire-reports/`、`backend/target/site/jacoco/`。本轮结果JSON保留证据摘要及源码哈希；后续修改需要重跑对应项。
