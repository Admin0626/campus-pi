# 选项C：商品发布收藏与分类

负责人：________

开发范围：本人负责本模块用户端页面、管理端页面、后端接口、数据库增量变更、测试及真实接口联调。

负责接口：API012、API015—API023、API079—API084；共16项，P0 16项、P1 0项。

16个接口主要是商品、收藏和分类的标准业务操作，因此数量略多。适合擅长列表表单、CRUD和前后端联调的成员。库存与订单交界必须和G联测。

## 接口清单

|接口编号|功能|请求方法与路径|阶段|
|---|---|---|---|
|API012|获取分类列表|`GET /categories`|P0|
|API015|查询公开在售商品|`GET /products`|P0|
|API016|获取商品详情|`GET /products/{product_id}`|P0|
|API017|查询本人发布商品|`GET /me/products`|P0|
|API018|发布商品|`POST /products`|P0|
|API019|替换本人商品资料|`PUT /products/{product_id}`|P0|
|API020|本人商品上架或下架|`POST /products/{product_id}/shelf`|P0|
|API021|收藏商品|`PUT /products/{product_id}/favorite`|P0|
|API022|取消商品收藏|`DELETE /products/{product_id}/favorite`|P0|
|API023|查询本人商品收藏|`GET /me/product-favorites`|P0|
|API079|查询全部商品及审核队列|`GET /admin/products`|P0|
|API080|审核商品|`POST /admin/products/{product_id}/review`|P0|
|API081|管理商品上下架|`POST /admin/products/{product_id}/shelf`|P0|
|API082|创建分类|`POST /admin/categories`|P0|
|API083|替换分类名称与描述|`PUT /admin/categories/{category_id}`|P0|
|API084|删除无引用分类|`DELETE /admin/categories/{category_id}`|P0|

## 必须完成的页面与组件

- 商品列表、详情、发布编辑、我的商品、商品收藏
- 商品审核及上下架、分类管理

## 公共职责

- 商品和分类数据访问、商品卡片与表单组件；商品可售规则
- 分类读取供D帖子使用；分类删除必须检查商品及帖子引用

## 前端组件与页面交接

- 商品列表、详情、发布、管理审核页面由C实现；详情中的下单入口使用G提供的下单表单或跳转G页面。
- 私信卖家入口调用H的会话发起组件；分类由C提供，D的帖子表单复用分类选项。

## 协作依赖与数据边界

- A/B提供登录、实名校园资格及商品图片上传；G维护订单和库存占用/释放过程
- G调用既有商品下单/取消过程后，C读取实时可售库存；双方不得再额外扣减库存
- D维护帖子分类引用，C删除分类前统一检查两个模块引用

## 建议开发顺序

- 先完成分类查询和公开商品列表，供页面和下单模块并行联调
- 再实现商品发布编辑审核及收藏，与G完成库存边界联测

## 本模块重点验收

- 非本人编辑、未认证发布购买资格与跨校区请求被阻止
- 发布/修改后重新待审；未通过或已下架商品不进入公开在售列表
- 未完结订单期间禁止改库存和关键内容
- 收藏重复提交不产生重复记录；分类被商品/帖子引用时禁止删除
- 与G并发下单/取消后库存正确，商品审核重复操作结果一致

## 全栈交付验收

- 本人独立交付本模块用户端与管理端页面、后端接口、数据库增量变更和联调记录；页面范围按本任务书逐项核对。
- 页面接入D提供的公共布局和导航，复用A的统一请求与登录状态；成功、加载、空数据、失败、无权限和未启用状态均有明确反馈。
- 表单按既定契约检查必填、长度、类型和枚举；列表分页和详情刷新正确；编号和金额按字符串处理，时间按界面时区展示。
- 标记幂等键的操作在同一动作重试时复用原键；提交期间避免重复点击，失败恢复后前后端状态一致，不能只靠按钮禁用保证唯一处理。
- 从真实浏览器经真实HTTP请求完成本人模块正常与失败流程，保留前后端联调证据；替身响应、页面截图或文档样例不算完整开发验收。
