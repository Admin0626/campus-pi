# 先读：九人协作边界与验收

这是一份基于已有112个HTTP契约的开发分工，不代表接口已经实现。已确认九位成员均按全栈模块分工：每人认领A—I中的一项，独立负责本模块用户端页面、管理端页面、后端接口、数据库增量变更、测试及前后端联调。列出的页面是本人必须完成的交付项。

分配依据是业务闭环、状态与数据一致性及公共基础设施，不按数量机械平均。8—16个接口不意味着工作量相差一倍；任务结算、文件隐私、异步投递较复杂。暂未得到成员技能和可投入时间，不给出虚构工时或按姓名强行分配。

## 唯一责任和公共能力

- 每个HTTP接口只有一个负责人；用户端和对应管理端归同一模块。协作测试不转移接口归属。
- A：工程入口、会话鉴权、职责权限、统一错误/响应/追踪、自动检查入口。
- B：文件与认证资格、私密访问、统一审计追加规范及审计查询。业务日志由各业务负责人按规范写入，不能只让B“查日志”而无人产生日志。
- C：商品与分类、分类引用检查。D：帖子、统计只读聚合、公共页面入口和导航。
- E：任务状态规范与发布申请分配。F：任务凭证验收、资金流水、幂等共用能力及恢复测试。
- G：订单读取和商品库存事务、数据库增量迁移的编号与顺序汇总。每个模块仍自行编写测试本模块迁移。
- H：私信交互和案件证据范围。I：通知快照/异步投递、运行配置与作业部署说明汇总。
- 九人均负责自己的页面和接口测试。D不代写全部页面，A不代写全部后端，G不代写全部迁移。
- A另负责前端统一请求客户端、登录状态及权限接入；D负责公共布局、导航和路由入口汇总。每个模块的表单、列表、详情、业务操作和页面错误处理仍由该模块本人交付。
- E拥有任务详情主页面，F提供嵌入其中的履约区组件；C拥有商品详情主页面，G提供下单表单或页面，H提供发起私信组件。详细页面归属与公共组件交接见“页面归属与联调验收.md”。

## 共享数据必须这样交接

|共享对象|规则与责任|
|---|---|
|users|A管理账号、资料、角色、禁用和会话；B只经认证审核事务更新认证字段。修改资料不得覆盖认证结果，角色变更需撤销会话。|
|reward_accounts / reward_ledger / task_settlement|F负责资金规则。A注册初始化账户；E发布/取消/发布审核过程按已有原子事务冻结或释放。各调用方不能重复发奖、冻结或释放。|
|RewardTasks / task_applications|E维护状态总表及发布申请分配；F维护凭证、验收与关闭分支。两人使用同一套状态约定和既有过程，不各自建互相矛盾的状态枚举。|
|user_orders|G维护类型映射与查询。E的任务分配过程创建任务订单，F的验收/关闭过程更新任务订单，均保留原有跨表原子范围。商品订单由G处理。|
|product_info库存|C负责商品管理；G的商品下单/取消过程预占或释放。C不得接到成功下单事件后再扣一次库存。|
|category / post_info引用|C管理分类，D写帖子分类引用；删除分类必须检查商品及帖子两侧引用。|
|文件元数据与file_ref|B唯一实现文件存储与访问；其他模块传用途、引用对象并调用校验，不能直接拼接永久公开地址。|
|admin_audit_log / task_audit_log|B维护通用审计入口；E/F沿用任务过程内部日志，其他管理员变更由自身业务操作落日志。|
|幂等记录|F提供持久化与恢复公共入口，各模块负责本接口请求摘要、业务唯一键和目标结果核对；不能只加一个内存缓存。|

这只是同一项目内的代码与数据职责划分，不要求拆成九个服务。现有存储过程内部有START TRANSACTION/COMMIT，不能再套调用方外层未提交事务。默认保留这些过程与原子范围；申请驳回等无过程分支补齐服务事务。若改为服务层等价事务，必须统一方案并重跑数据库与并发验收，不能逐人混搭导致部分提交。

## 并行顺序

1. **先对齐公共契约**：九人共同过一遍既有OpenAPI；A提供鉴权/错误样例，B提供文件引用和认证检查，E/F/G确认任务—资金—订单交接；F给出幂等接入约定，G登记迁移顺序，D给页面入口规范。
2. **各模块并行做P0**：使用合成数据和契约样例独立开发；基础依赖未完成时可用明确标注的替身联调，不把替身测试标记为真实集成通过。B认证与C商品、E/F任务、G订单均先有可验证的基本闭环。
3. **联合验收关键链路**：A/B/C/G验收注册认证→商品审核→下单取消；A/B/E/F/G验收任务冻结→申请分配→凭证→唯一结算；H验收私信举报；I验收通知快照投递；D负责入口整合及统计对账，每位接口负责人修复自己的失败项。
4. **最后开展P1**：A的找回密码2项；G的交易/支付/售后6项。补模型、外部供应商与沙箱条件齐备后单独验收。未启用保持原契约501，不因“分配完成”宣布支付上线。

## 每人统一交付和完成标准

- 本模块接口实现，保持原API编号、路径、请求响应、权限、状态、分页与错误约定；不得自行增加“方便调用”的新业务接口。
- 本模块数据库增量迁移及回滚/恢复说明、配置样例（不含真实密钥）、合成测试数据；不要覆盖既有数据库。
- 本人完成本模块用户端/管理端页面及其真实接口联调；接入公共布局、统一请求和登录状态，附请求样例与失败场景说明。
- 页面需覆盖加载、空数据、失败、无权限和P1未启用状态；表单校验、分页、重复点击控制、幂等重试和操作后刷新与后端契约一致。后端必须独立校验权限及唯一处理，不能依赖前端按钮限制。
- 真正执行的正常、越权/未认证、参数错误、状态冲突和重复提交测试记录；资金/库存/分配/投递另做并发与中断恢复测试。
- 交付中注明已实现、实测通过、尚未验证、P1未启用；接口文档/样例/SQL测试不能代替真实HTTP联调证据。
- 跨模块联测通过，迁移可按登记顺序在独立测试数据库执行，运行配置与启动说明完整。每项P0有实际测试证据后才可标完成。

## 文本认领方式

九位成员在“校园Π九人全栈分工说明”的负责人栏各填写一项，由一人汇总核对。每项任务书按API编号对应配套原接口文档，无需使用网页。
