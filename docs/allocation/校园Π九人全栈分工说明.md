# 校园Π九人全栈分工说明

采用文本任务书配套现有接口文档。本文提到的docs/api路径以仓库根目录为起点。九位成员各选A—I中的一项，每人完成自己模块的前端、后端、数据库增量变更与测试联调。负责人暂留空，待团队选择后填写。

线下交易最新规则以[接口变更](../api/线下交易接口变更.md)、OpenAPI及Markdown为准，原Word为历史设计档案。其他接口参数、响应和业务规则沿用“docs/api/校园Π接口开发规范.docx”、同名Markdown及campus-pi-openapi.json。分工说明按API编号定位，不重复定义协议，也没有交互网页。

分工按业务闭环和复杂度安排：B的文件隐私、F的资金结算接口少但测试较重；C常规操作较多；G含3个任务争议相关P1接口，商品改为线下交易。成员能力与时间尚未提供，以上为可认领选项，不虚构个人工时。

## 每个人的共同交付

- 本人模块的用户端和管理端页面及组件，接入公共布局、导航、统一请求与登录权限。
- 本人负责的后端接口与数据库增量变更，严格沿用API编号、方法路径和字段规则。
- 正常、参数错误、无权限、状态冲突和重复提交场景的真实前后端联调记录；资金、库存、分配和投递另验证并发与中断恢复。
- 配置样例、合成测试数据、迁移及启动说明，注明已实现、实测通过、未验证和P1未启用。

## 公共部分与页面交接

- A负责服务端基础鉴权及前端统一请求、登录状态和权限接入；D负责公共布局、导航和各模块页面入口汇总。各人自行开发自己的业务页面。
- B提供上传和私密预览组件；各模块按文件用途和引用对象复用，不能绕过后端权限。
- E负责任务详情主页面，F负责其中凭证、验收与结算组件；E接入组件，双方统一任务状态及刷新。
- C负责商品详情，G提供下单页面或组件，H提供发起私信组件。
- F提供资金、幂等及恢复规范；G汇总数据库迁移顺序；I负责通知作业与运行配置说明汇总。各模块仍由本人写迁移、接入并完成测试。
- H提供私信未读入口，I提供通知未读入口，D接入导航；两类未读状态分别维护。

## 使用顺序

1. 九人各选一个选项，在上方负责人栏填写姓名；由一人汇总，确保每人一项、每项一人。
2. 各人阅读本人任务书、协作边界、页面归属及原接口文档中对应API。
3. 先确认公共接入与E/F/G的任务—资金—订单交接，再并行开发P0。
4. 各人完成模块内真实联调，再联合验证注册认证→商品下单取消、任务发布→分配→验收结算、私信举报和通知投递。
5. 最后按条件开展P1：A的密码找回2项，G的任务争议相关3项。未接通时保持原契约未启用行为。
